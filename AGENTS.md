# Repository instructions

Write distribution content in English. Keep each skill portable from its own directory. Read only the skill resources relevant to your task.

- Use synthetic fixtures and public references. Keep private source materials, provenance records, raw transcripts, personal identifiers, and credentials outside this repository.
- Propose new distribution files explicitly and review their provenance before committing. Keep documents, fixtures, and tool output within the authorization granted for the task.
- Keep skills small and state when they apply, expected evidence, and the completion condition. Move optional detail into referenced files.
- Use plain single-line name and description frontmatter. Keep local Markdown paths repository-relative and skill resources inside their package. Add an observable evaluation case when behavior changes.
- Run the deterministic checks in the README. Record live client observations separately from package checks and controlled evals.
- Require maintainer approval before releasing, publishing, enabling external execution, or changing distribution scope. Follow the release checklist.
