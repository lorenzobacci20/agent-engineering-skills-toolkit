# Contributing

Start with the engineering decision a skill should improve. Describe the trigger, evidence it should request, measurable result, relevant authorization boundary, and failure mode. Check the catalog for a procedure that can absorb the improvement.

Keep a skill installable by itself. Link optional resources from its entry point and keep links within that skill. Add synthetic examples for material branches. Add or update observable eval criteria, including negative cases when a scope or evidence rule changes.

Run the [deterministic checks](README.md#how-it-works). If dependent behavior changed, also run the relevant [eval case](docs/evaluation.md). Include the environment, revision, evidence, and limits in the change description. Contributions must be suitable for the project's [MIT distribution](LICENSE), with any proposed third-party material and required attribution disclosed to the maintainer before inclusion.
