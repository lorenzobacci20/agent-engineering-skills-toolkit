# Checkpoint worksheet

| Field | What to capture |
| --- | --- |
| Statement and scope | A single claim and the projects or sessions it applies to |
| Kind | Fact, decision, historical observation, or hypothesis |
| Evidence | Source and observed/effective date where relevant |
| Destination | Authoritative owner and record, or an existing anchor |
| Action | Update, candidate, deduplicate, skip, or defer |
| Candidate condition | The evidence required for promotion and when to revisit |
| Verification | Record reread, links checked, or write still pending |

Synthetic examples

- A maintainer explicitly chose integer cents for a sample API. Record it in the project decision log with the decision reference.
- A single flaky test log suggests a locale dependency. Record the hypothesis in the project tracker only if useful. Promote it to a known cause after a controlled locale comparison.
- A handoff repeats a verified support window. Link to the existing policy at its effective version.
- A newer reliable result narrows an old deployment observation to a single region. Correct the current claim and keep the old receipt as historical evidence if the change matters.
